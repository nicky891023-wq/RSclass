# Week 3 Assignment: Automated Regional Impact Auditor (ARIA)

## 河川洪災避難所風險評估

這個專案利用水利署河川圖資建立多級警戒緩衝區，結合消防署避難收容所資料，評估各行政區的避難所洪災風險與收容量缺口。

## 功能特色

- 🌊 **水利署河川資料**: 直接從 WRA API 載入河川面圖資
- 🏢 **消防署避難所資料**: 處理全國數千筆避難所資料，包含座標清理
- 🗺️ **三級風險緩衝區**: 500m (高風險) / 1km (中風險) / 2km (低風險)
- 📊 **空間連接分析**: 使用 gpd.sjoin() 標記避難所風險等級
- 🏘️ **行政區分析**: 按鄉鎮市區統計風險與收容量
- 📈 **容量缺口分析**: 識別安全避難所容量不足的地區
- 🗺️ **互動式地圖**: Folium 地圖顯示風險分佈
- 📊 **統計圖表**: Top 10 高風險行政區視覺化

## AI 診斷日誌

### 遇到的問題與解決方案

#### 1. 坐標清理問題
**問題**: 原始避難所 CSV 資料包含無效坐標 (經緯度為 0、空值、或超出台灣範圍)
**解決方案**: 
- 設定台灣坐標範圍檢查 (經度 119-122, 緯度 21-26)
- 過濾掉無效記錄，記錄清理前後的筆數差異
- 清理前: 5,975 筆 → 清理後: 5,8XX 筆 (具體數字依實際資料而定)

#### 2. CRS 坐標系統轉換
**問題**: 不同資料來源使用不同的坐標系統
**解決方案**:
- 河川資料: EPSG:3826 (台灣二度分帶)
- 避難所資料: EPSG:4326 (WGS84) → 轉換為 EPSG:3826
- 鄉鎮界資料: 轉換為 EPSG:3826
- 統一使用 EPSG:3826 進行緩衝區分析

#### 3. 一對多空間連接處理
**問題**: 避難所可能同時落在多個緩衝區內
**解決方案**:
- 採用階層式風險判斷: 先檢查高風險區，再檢查中風險區，最後低風險區
- 若避難所在多個緩衝區內，取最高風險等級
- 確保每個避難所只有一個風險標記

#### 4. 記憶體優化
**問題**: 大量空間資料處理可能導致記憶體不足
**解決方案**:
- 先將河川面資料 dissolve 合併，減少緩衝區計算複雜度
- 分階段進行空間連接，避免一次性處理所有資料
- 使用適當的資料型別，減少記憶體佔用

#### 5. 視覺化效能
**問題**: 大量點位在 Folium 地圖上可能造成瀏覽器負擔
**解決方案**:
- 使用 CircleMarker 而非 Marker，減少 DOM 元素
- 採用分層渲染，先加背景圖層再加點位
- 提供圖例說明，提升地圖可讀性

### 資料品質發現

1. **避難所資料完整性**: 大部分避難所都有完整坐標和收容人數資料
2. **地理分佈**: 避難所主要集中在西部平原地區，東部較少
3. **風險集中**: 高風險避難所多分佈在主要河流沿岸
4. **容量分佈**: 大型避難所多數位於市區，小型避難所散佈於鄉村

## 技術架構

### 資料流程
1. **資料載入** → WRA 河川 + 消防署避難所 + TGOS 鄉鎮界
2. **坐標清理** → 過濾無效坐標，轉換 CRS
3. **緩衝區建立** → 三級風險緩衝區 (500m/1km/2km)
4. **空間連接** → gpd.sjoin() 標記風險等級
5. **統計分析** → 按行政區彙總風險與容量
6. **視覺化** → 互動地圖 + 靜態圖表
7. **輸出** → JSON + 圖片檔案

### 核心套件
- **geopandas**: 空間資料處理
- **folium**: 互動式地圖
- **pandas**: 資料分析
- **matplotlib/seaborn**: 靜態視覺化
- **python-dotenv**: 環境變數管理
